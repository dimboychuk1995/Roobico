# CLAUDE.md

Инструкции для Claude Code при работе с проектом Roobico.

## О проекте

Roobico — мультитенантный SaaS для автосервисов и флитов: work orders, запчасти,
клиенты/юниты, инвойсы, платежи, биллинг подписок через Stripe, клиентский портал.
Стек: Flask + PyMongo (без ORM), Jinja2 + Bootstrap 5 + vanilla JS/jQuery (CDN, без сборки).

## Базы данных — КРИТИЧНО

- Сервер `198.199.122.49`:
  - порт **27017 — база DEVELOP** (локальный `.env` смотрит сюда);
  - порт **27018 — база PROD**. **В прод лезем ТОЛЬКО когда пользователь явно об этом говорит.**
- Тесты используют локальный Mongo `127.0.0.1:27017` — `tests/conftest.py` жёстко
  подменяет URI и работает только с тестовыми базами; серверные базы не трогает.
- Устройство: `master_db` (tenants, users, shops, audit_journal) + отдельная база
  на каждый магазин (`db_name` в документе shop).

## Деплой

- Деплоим только через `deploy/deploy_prod.ps1` — **перед деплоем прочитать и
  проверить сам скрипт**. Он деплоит ветку `production`, делает healthcheck
  `/healthz` через unix-сокет gunicorn и автоматически откатывается на предыдущий
  коммит при провале.
- SSH-ключи для подключения к серверу: `C:\Users\User\Desktop\roobico\`.
- После деплоя фич, меняющих поисковые поля, прогнать бэкфилл на нужной базе:
  `python -m app.scripts.backfill_search_terms`.
- Включение транзакций Mongo на сервере: `deploy/enable_replica_set.md`.
  Gunicorn-конфиг: `deploy/gunicorn.conf.py` (systemd-юнит должен запускать с `-c`).

## Бэкапы прода

- На сервере: cron root'а ежедневно в 03:00 UTC запускает
  `/usr/local/bin/mongo_backup.sh` — mongodump прода (27018) в
  `/var/backups/mongo/`, хранится 7 последних архивов, лог в
  `/var/log/mongo_backup.log`.
- Офсайт-копия: задача Windows Task Scheduler «Roobico prod backup pull»
  ежедневно в 10:00 запускает `deploy/pull_prod_backup.ps1` — скачивает
  свежий архив в `C:\Users\User\Backups\Roobico` (хранится 14 копий).
- Алерт: если свежий бэкап на сервере старше 30 часов или выгрузка не удалась,
  на рабочем столе появляется `ROOBICO-BACKUP-PROBLEM.txt` с причиной.
- Перед любыми рискованными операциями на проде — проверить свежесть бэкапа.

## Frontend

- **Любое изменение UI делается сразу под ОБЕ темы** — светлую и тёмную
  (`static/css/theme_dark.css`, переключение через `data-theme`). Проверять вид
  в обеих темах перед завершением задачи.
- **Типовые элементы — таблицы, модальные окна, формы, кнопки, бэджи и т.п. —
  оформляются только общими классами**, без копий стилей на отдельных страницах.
  Дизайн должен меняться в одном месте для всего приложения, а не постранично.
  Перед созданием нового компонента искать существующий класс/паттерн и
  переиспользовать его.
- CSRF в JS автоматический: `static/js/csrf.js` подключён первым в базовых
  layout'ах и добавляет `X-CSRFToken` ко всем fetch/XHR и скрытое поле в POST-формы
  (включая динамически созданные). Руками токен в новый JS-код не добавлять.
- Статика версионируется автоматически (`?v=ASSET_VERSION` через url_defaults) —
  ручные `?v=` в шаблонах не писать.
- Ошибки AJAX показывать пользователю (toast/SweetAlert), не только в console.

## Архитектура кода

- `app/blueprints/<домен>/routes.py` — тонкие HTTP-хендлеры.
- Бизнес-логику выносить в сервисный слой — образец:
  `app/blueprints/work_orders/services/` (common, totals, payments, inventory,
  lookups, listing, pdf_contexts, authorizations). Новую логику НЕ добавлять
  в routes.py портянками.
- Общие хелперы в `app/utils/`:
  - `tenant.py` — `oid`, `tenant_id_variants`, `get_shop_db` — **единственный
    способ получить shop-базу** (проверяет принадлежность магазина тенанту);
  - `mongo_tx.py` — `run_atomically` для связанных записей (платёж + статус WO);
  - `entity_search.py` — поиск через `search_terms`;
  - `rate_limit.py`, `permissions.py`, `display_datetime.py`, `contacts.py`.

## Инварианты (не ломать)

- **Изоляция тенантов**: shop-база только через `get_shop_db`; в запросах по
  shop-коллекциям — фильтр `shop_id`; в master-коллекциях — `tenant_id`.
- **Права**: каждый роут — `@login_required` + `@permission_required("...")`.
- **CSRF** включён глобально. Новые формы получают
  `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">`.
  Новые исключения — только `@csrf.exempt` с обоснованием (webhook / token-аутентификация).
- **Деньги**: округление через `round2`; связанные денежные записи — через
  `run_atomically` с прокидыванием `session=` во все операции внутри callback.
- **Поиск**: при добавлении/изменении полей customers/units/parts обновить
  `build_*_search_terms` во всех местах записи + прогнать бэкфилл.
- **Даты**: в Mongo хранится UTC; отображение — через `app/utils/display_datetime`
  (таймзона магазина). В шаблонах не форматировать даты вручную.
- **Ошибки не глотать**: никаких голых `except Exception: pass` — логировать через
  `current_app.logger.exception(...)`. Глобальные обработчики 404/500 уже есть.
- **Индексы**: новые паттерны запросов сопровождать индексами в
  `app/extensions.py` (`ensure_*_indexes`, через `_safe_create_index`).

## Тесты

- Запуск: `python -m pytest` (~5 сек, нужен локальный Mongo).
- Новые эндпоинты и фичи сопровождать тестами в `tests/`. Фикстуры (тенанты,
  магазины, владелец, `login`, `get_csrf_token`) — в `tests/conftest.py`.
- POST-запросы в тестах требуют CSRF-токен — использовать `get_csrf_token(client)`.
- После любого рефакторинга прогонять весь набор; для правок в незакрытых тестами
  путях дополнительно `python -m pyflakes` по изменённым пакетам.
