Set it up

{% call step(1, "Turn on the inbox") %}

Settings → Integrations → Parts orders from email → {{ ui("Turn on") }} (needs {{ perm("settings.manage_integrations", "Manage integrations") }}). The switch saves immediately and shows the location's private address, like orders-a1b2c3d4e5f6@roobico.com, that only the AI reads.

{{ shot("settings-email-orders-modal", "Parts orders from email: the switch, the address and forwarding instructions.", "md") }} {% endcall %} {% call step(2, "Forward vendor mail there") %}

Either set auto-forwarding in the mailbox where vendors write you (Gmail: Settings → Forwarding; Outlook: Settings → Mail → Forwarding — step-by-step instructions for every provider are under How to set up forwarding), or add the address as an extra notification email in the vendors' portals. Forwarding everything is fine — non-orders are ignored. Gmail / Yahoo / iCloud / Zoho send a confirmation code to the new address first: open that email with {{ ui("View") }} under Recent emails.

{% endcall %}

What happens with every email

  1. PDFs first. Every PDF or image attached is read by the same engine as the AI Order Reader. An order document (confirmation, invoice, packing slip) with itemized lines makes the email an order and the lines come from the PDF. A quote, statement or receipt is not an order. Only the first six pages are read; Excel / Word / ZIP and files over 6 MB are listed as Not read with the reason.
  2. Then the text, only when there is no decisive attachment: vendor, vendor order / invoice number, date and lines. Quotes, tracking notices, promos and the like are marked Ignored — kept in the history, convertible to an order with one click.
  3. Vendor is matched by name, then by a sender address learned from earlier orders, then by AI against your vendor list. No match → the vendor is created automatically with the contacts from the email.
  4. Parts are matched by part number (separators ignored). Unknown lines are kept as unmatched lines for you to resolve.
  5. Duplicates: the same vendor number in Vendor Bill, or a hand-typed order in the last three weeks with the same parts and quantities → the email is linked to that order instead of creating a second one.
  6. The order is created with status ordered, the vendor number in Vendor Bill, the email files as attachments and the red Not confirmed badge. Office users get a push notification.

Confirm or reject

{% call step(1, "Find it") %}

Parts Orders tab → filter Not confirmed (from email), or {{ ui("Review") }} in the yellow banner. Until a person confirms, the order is on hold: it cannot be received, paid or returned and is not counted in balances, dashboard purchases or reports.

{{ shot("parts-orders-tab", "The Parts Orders tab — Not confirmed orders carry a red badge.") }} {% endcall %} {% call step(2, "Confirm") %}

Click the red {{ ui("Confirm") }} (or Edit). The dialog opens with a yellow “Created from email” block: sender, subject, vendor number, a warning if the vendor was auto-created, and Lines not found in the parts catalog with {{ ui("Create & Add") }} per line. Check quantities and prices, then {{ ui("Confirm order") }} — from now on it is a normal order. Confirming needs {{ perm("parts_orders.edit", "Edit parts orders") }}.

{% endcall %} {% call step(3, "Reject") %}

{{ ui("Reject") }} removes the order when the email was not an order for this shop; the email stays in the history as Rejected and an auto-created vendor is deleted again.

{% endcall %}

Suggest-only mode and the history

In the integration settings choose Suggest only while you get used to the feature: AI reads the email but creates nothing; the history shows Needs review and you press {{ ui("Create order") }}. Inbox history (same window) lists every email with its result — Order created, Linked to order, Ignored (with AI's reason), Needs review, Error — and actions View / Create order / Retry / Ignore. If nothing appears within a couple of minutes, the forwarding rule on the mail side is not active.

{% call tip("Vendor created twice?") %} Open the order, pick the right vendor from the list and save (or Confirm): the auto-created duplicate is deleted and the sender is remembered for the vendor you chose. {% endcall %}
