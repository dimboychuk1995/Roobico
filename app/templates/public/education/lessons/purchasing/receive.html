Receiving needs {{ perm("parts_orders.receive", "Receive / un-receive parts orders") }}.

{{ shot("parts-orders-tab-with-order", "An ordered, unpaid order on the Parts Orders tab with its actions.") }} {% call step(1, "Receive Order") %}

Click {{ ui("Receive") }} in the row (or the yellow ordered status, or Receive inside the order dialog). If you changed quantities, prices or lines in the order dialog first, those edits are saved automatically when you press Receive, and the receiving dialog opens with the saved numbers.

{{ shot("parts-order-receive", "The receive dialog: vendor bill, then one row per line with Ordered and Received (plus Location when the shop uses storage locations).", "md") }} {% endcall %} {% call step(2, "Vendor Bill") %}

Enter the vendor's invoice number (optional). It is searchable later and used to detect duplicate email orders.

{% endcall %} {% call step(3, "Received — what actually arrived") %}

Every line of the order is listed, including “do not track inventory” parts and parts that are currently inactive (an Inactive badge — receiving makes them active again). The Received column is prefilled with the ordered quantity. If the vendor shipped fewer or more, type the real number: the order is updated to what was received, the original number stays on the line as “ordered N”, and 0 removes the line from the order. The order total therefore always equals the vendor bill.

{% endcall %} {% call step(4, "Location") %}

If the shop uses locations, pick where each received part goes in the Location column — default is the part's primary location, otherwise Unassigned. A location chosen here becomes the part's default if it had none. Untracked parts have no location (shown as “—”).

{% endcall %} {% call step(5, "Confirm") %}
  • Stock increases by the received quantities.
  • The part's average cost is recalculated as a weighted average of old stock and the received price (if stock was zero / negative or the average was 0, the received price becomes the average).
  • “Do not track inventory” parts get no stock movement — only their average cost is set to the received price.
{% endcall %} {% call note("Payment guard and the mobile app") %} If a payment already recorded on the order is larger than the new (received) total, receiving is refused — delete or correct that payment on the Parts Orders Payments tab first. The mobile app has only the Vendor Bill field and receives every line as ordered; partial receipts are web-only. {% endcall %}

Unreceive

{{ ui("Unreceive") }} rolls the received quantities back out of the same locations and takes that batch back out of the average cost, so re-receiving does not count it twice. It always works — even when the parts were already used on work orders: stock then goes below zero and a warning lists those parts (e.g. “BRK-100 (−3)”); it corrects itself when the order is received again or the stock is adjusted. The only thing that blocks it is an active return on the order — delete the returns first.

{% call note("Received orders are frozen") %} They cannot be edited — Unreceive first. Deleting a received order does not require un-receiving: it rolls the stock back itself (the same way, with the same below-zero warning) and deactivates the order's payments; like Unreceive, it is blocked only while the order has active returns. Orders from email that are still Not confirmed cannot be received at all — confirm them first. {% endcall %}
