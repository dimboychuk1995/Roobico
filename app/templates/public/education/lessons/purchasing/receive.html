Receiving needs {{ perm("parts_orders.receive", "Receive / un-receive parts orders") }}.

{{ shot("parts-orders-tab-with-order", "An ordered, unpaid order on the Parts Orders tab with its actions.") }} {% call step(1, "Receive Order") %}

Click {{ ui("Receive") }} in the row (or the yellow ordered status, or Receive inside the order dialog).

{{ shot("parts-order-receive", "The receive dialog: vendor bill and locations.", "md") }} {% endcall %} {% call step(2, "Vendor Bill") %}

Enter the vendor's invoice number (optional). It is searchable later and used to detect duplicate email orders.

{% endcall %} {% call step(3, "Where to put the parts") %}

If the shop uses locations, choose Put received parts into: for each line — default is the part's primary location, otherwise Unassigned. A location chosen here becomes the part's default if it had none.

{% endcall %} {% call step(4, "Confirm") %}
  • Stock increases by the received quantities.
  • The part's average cost is recalculated as a weighted average of old stock and the received price (if stock was zero / negative or the average was 0, the received price becomes the average).
  • “Do not track inventory” parts get no stock movement — only their average cost is set to the received price.
{% endcall %}

Unreceive

{{ ui("Unreceive") }} rolls the received quantities back out of the same locations and takes that batch back out of the average cost, so re-receiving does not count it twice. Not possible while the order has active returns.

{% call note("Received orders are frozen") %} They cannot be edited; delete requires un-receiving first. Orders from email that are still Not confirmed cannot be received at all — confirm them first. {% endcall %}
