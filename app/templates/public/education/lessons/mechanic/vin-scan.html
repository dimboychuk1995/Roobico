  • Scanning the VIN barcode with the camera.
  • The three outcomes: known unit, several companies, unknown VIN.
  • NEW Customer and the office's Transfer fix.
{% endcall %} {% call step(1, "Scan VIN") %}

On the new work order screen, before picking anything, tap {{ ui("Scan VIN") }}. Point the camera at the VIN barcode (door-jamb sticker, dashboard plate — Code 39 / 128, DataMatrix, QR). The VIN is picked up automatically — no buttons to press; a flashlight toggle helps in dark cabs. Other barcodes are ignored; only a valid 17-character VIN triggers.

{% endcall %} {% call step(2, "What happens next") %}
  • The VIN belongs to an existing unit → the customer and unit are filled in and the work order starts — unless that unit already has a work order In Progress, in which case that work order opens (one truck = one work order).
  • The same VIN is active on several companies → the app asks which company this job is for.
  • The VIN is not in the system → a new unit is created automatically under the technical customer NEW Customer (make / model / year decoded from the VIN) and the work order starts on it.
{% endcall %} {% call step(3, "The office re-homes it") %}

Later, on the web work order, the office presses {{ ui("Transfer") }} and picks the real company. The unit follows automatically and the real company's labor rates, part prices and tax flag are re-applied; the mechanic can keep working meanwhile. See {{ lesson_link("work-orders/transfer") }}.
