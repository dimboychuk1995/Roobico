Deactivating

Customer page → {{ ui("Deactivate Customer") }} (needs {{ perm("customers.deactivate", "Deactivate customers") }}). Unit page → Details → {{ ui("Deactivate Unit") }}. Nothing is deleted: history, work orders, units and balances stay (the single exception is the system customer NEW Customer — its stray units that carry no history at all are deleted by the nightly cleanup, see below). Inactive customers and units are hidden from work order pickers, the mobile app and the customer portal until activated.

Activating back

Open the customer → {{ ui("Activate Customer") }}; open the unit → Details → {{ ui("Activate Unit") }}. Everything is where it was. Creating a new customer with the name of a deactivated one is blocked — the message tells you to activate the existing record instead.

“NEW Customer”

If mechanics scan VINs in the mobile app, the shop gets a technical customer named NEW Customer. Unknown VINs are filed under it so work can start immediately. This customer cannot be deactivated. Instead, move its work orders to the real company with the {{ ui("Transfer") }} button on the work order page — the unit follows automatically. See {{ lesson_link("work-orders/transfer") }}. Stray units — scanned but never given a work order, or left behind after a Transfer — need no manual clean-up: every night the system deletes units under NEW Customer that have no work order, appointment, inspection or attached file (anything scanned in the last six hours is left alone). A unit with a work order stays until that work order is transferred. After the Transfer the original unit left behind under NEW Customer (deactivated when the Transfer created a copy for the real company, or simply no longer linked when the company already had that VIN) is deleted the next night — unless it still has attached files, an annual inspection or an appointment of its own, which Transfer does not move; move or delete those first.

{% call note("No merge") %} There is no customer merge feature. If two records describe the same company, keep one, transfer any work orders from the other, then deactivate it. {% endcall %}
