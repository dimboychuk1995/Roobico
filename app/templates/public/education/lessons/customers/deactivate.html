Deactivating

Customer page → {{ ui("Deactivate Customer") }} (needs {{ perm("customers.deactivate", "Deactivate customers") }}). Unit page → Details → {{ ui("Deactivate Unit") }}. Nothing is deleted: history, work orders, units and balances stay. Inactive customers and units are hidden from work order pickers, the mobile app and the customer portal until activated.

Activating back

Open the customer → {{ ui("Activate Customer") }}; open the unit → Details → {{ ui("Activate Unit") }}. Everything is where it was. Creating a new customer with the name of a deactivated one is blocked — the message tells you to activate the existing record instead.

“NEW Customer”

If mechanics scan VINs in the mobile app, the shop gets a technical customer named NEW Customer. Unknown VINs are filed under it so work can start immediately. This customer cannot be deactivated. Instead, move its work orders to the real company with the {{ ui("Transfer") }} button on the work order page — the unit follows automatically — and edit or deactivate its stray units like any others once they are re-homed. See {{ lesson_link("work-orders/transfer") }}.

{% call note("No merge") %} There is no customer merge feature. If two records describe the same company, keep one, transfer any work orders from the other, then deactivate it. {% endcall %}
