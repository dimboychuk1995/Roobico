Entities

EntityColumns and rules
CustomersCompany Name, First / Last Name, Phone, Email, Address, Pricing Scale Name. The shop needs at least one labor rate.
UnitsPer customer: pick the customer in Import units for customer first — every row is linked to that customer (one file per customer; a Customer Name column in the file is ignored, rows of another customer are skipped and reported). Columns: Unit Number, VIN, Year, Make, Model, Type, Mileage. A row needs a Unit Number or a VIN; a VIN the customer already has is skipped.
VendorsVendor Name (+ contact, phone, email, website, address, notes).
PartsPart Number, Description, Reference, In Stock, Average Cost, Selling Price. Starting stock gets a location row and an “initial” movement.
Work OrdersHistorical records: Date and Customer Name required; unit matched by Unit Number or VIN within that customer; Status open / in_progress / completed / paid (default completed). Labor Total (or Hours), Parts Total and Sales Tax build the totals; a paid row also records the payment (or the Paid Amount column). An existing WO Number is skipped; leave it empty to auto-number.
{{ shot("import-export-units", "Units import: pick the customer first.") }} {% call warn("Duplicates are rejected, never merged") %} A customer, vendor or part that already exists in the shop (same name / part number, case-insensitive) is skipped and listed — including repeats inside the file. If the existing record is deactivated, the error says so: reactivate it instead of importing a copy. {% endcall %} {% call tip("Recommended order") %} Customers → Units (one file per customer) → Vendors → Parts → Work Orders. Re-running a file is safe: duplicates are skipped and reported. {% endcall %}
